# `/damn prompt` · Prompt 门禁（ID: `damn.gate.prompt`）

只在 `/damn prompt <原文>` 时使用。目标是把用户的 prompt 改到能直接执行，然后停止。不做调研。

## 做三件事

1. **改错**：消解「这个 / 那个 / 刚才 / 最新的 X」等指代；修笔误和产品、术语名；删掉重复和互相矛盾的话。
2. **补全**：把对话、打开的文件、附件里已经明确的信息写进 prompt（对比对象、路径、环境、约束）。
3. **标缺失**：上下文里没有、又会改变结果的信息，列出来，不猜。

确认指代时可以读或搜本地文件，几次调用以内；不做外网检索。

不改用户意图。不加新目标、新对比对象或新维度。不套 CoT、角色扮演之类的模板。

## 输出

1. 修正后的 prompt：一个代码块，可直接粘贴给 `/damn` 或其他 agent。
2. 改了什么：最多 3 条，一句一条。
3. 缺失：最多 3 条，只列会改变结论的；没有就写「无」。

原文已经清楚时，原样返回，并说明无需修改。

## 停止条件

prompt 能直接执行就停。不出阶段卡片，不开始调研。

只有缺了某项就写不出可用的 prompt 时，才问一个问题，用它代替上面的输出。

`$ARGUMENTS` 在 `prompt` 之后为空时，改写对象是用户的上一条消息。

## Deep 变体（`/damn prompt deep <原文>`，ID `damn.gate.prompt.deep`）

`prompt` 后第一个词是 `deep` 时启用。目标是更深，而不是更大。

先完成上面的改错和补全，再简短回答（每问 1–3 行）：

1. 这个领域的顶尖专家会做哪些用户没要求的事；
2. 他们会从哪些最原始的素材入手，而不是已经整理好的素材；
3. 他们会用哪些具体方法和工具；
4. 除了你我之外，什么能证明结果是对的（写成可执行的检查：测试、脚本、指标、一手数据或官方文档）。

然后按这四点改写 prompt。只加「怎么做」，不扩大目标、范围或对比对象。

输出：四问回答 → 修正后的 prompt → 缺失。仍然在改写后停止。
